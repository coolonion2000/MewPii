# Codex 连接恢复（尚需授权部署）

## 已有证据

2026-09-10 的 Pi 会话记录包含 WebSocket 连接 15 秒超时、降级 SSE，以及 SSE 响应头等待 300 秒超时。短对话也有连接失败，因此大上下文不是唯一解释。OAuth 账号相同不能证明客户端连接、上下文、恢复策略相同；目前没有确定故障最初发生在网络路径还是服务端。

## 本次策略

- 服务启动时使用所安装 Pi SDK 的 Undici 初始化逻辑，仅初始化一次；保留显式代理环境变量，不写用户设置或凭据。
- 仅包装主会话中 `openai-codex` 的请求，保留 SDK 的认证、扩展请求钩子和响应钩子；不直接修改 `node_modules`。
- 健康 WebSocket 保持复用；降级后冷却 60 秒，在下一次请求开始前仅清理该会话的失效连接与降级标记，允许重新连接。不在正在输出时切换或重放请求。
- WebSocket 建连最多 10 秒，SSE 等待响应头最多 60 秒；收到响应头后取消这个短计时器，后续思考/输出仍由原有空闲超时控制。
- 禁止叠加 provider 层重试；Codex 会话自动重试最多 1 次（原本禁用重试仍保持禁用）。非 Codex 模型不受影响。停止信号仍传递给实际请求。
- UI 分别显示准备、连接、SSE 响应头等待、已收到响应、重试及计时；状态进入会话快照，重连可恢复，结束时清除。新增日志只记录会话 ID、传输方式、阶段和耗时，不记录请求正文或认证头。

## 验证边界

- `node --import tsx --test server/test/codex-transport.test.mjs server/test/provider-network.test.mjs`
- `npm run test -w web`、协议同步检查、服务端 TypeScript 检查。
- `node web/test/serve-provider-activity.mjs` 提供独立、内存构建的状态交互验证页，不连接运行中的服务。
- 服务端完整回归在隔离输出目录执行；不覆盖 `server/dist` 或 `web/dist`。旧 `context-mode-repair` 测试因复制到临时目录的原始备份已存在而失败，在原测试目录也可独立复现。

这些验证证明恢复逻辑和状态流，不代表真实 OpenAI 请求延迟已经下降。没有改模型、降低推理强度、压缩用户会话或提高收费档位。需要用户授权重启后，再观察真实会话的首响应耗时与恢复情况。
